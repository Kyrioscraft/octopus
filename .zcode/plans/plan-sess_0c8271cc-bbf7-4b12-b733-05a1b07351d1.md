## 目标
修复聊天实时输出时强制滚动打扰用户查看历史的问题，实现"智能跟随"：仅当用户贴底时自动跟随新输出；用户向上滚动时不打扰；用户滚回底部后自动恢复跟随。并在未贴底时显示"回到底部"浮动按钮。

## 改动文件（3 个）

### 1. 新建 `web/src/hooks/useStickToBottom.ts`
封装贴底跟随逻辑的 hook，签名：
```ts
const THRESHOLD = 80; // 距底部 80px 内视为贴底
const { scrollContainerRef, isStuck, scrollToBottom } = useStickToBottom();
```
- `scrollContainerRef`: 绑定到滚动容器（`Chat.tsx:140` 的 `overflowY:auto` div）
- 内部 `stickRef`（useRef）记录贴底状态，保证流式回调读到最新值不滞后
- 在 `scrollContainerRef` 上注册被动 `scroll` 事件：`scrollTop + clientHeight >= scrollHeight - THRESHOLD` 更新 `stickRef`；只有跨越阈值（true↔false）时才 `setIsStuck`（避免每个像素触发重渲染）
- `scrollToBottom(opts?: { force?: boolean; smooth?: boolean })`：
  - `force=false`（默认）：仅当 `stickRef.current === true` 才执行 `scrollContainer.scrollTop = scrollHeight`
  - `force=true`：无条件滚动（按钮点击/发送新消息时用）
  - `smooth`：默认流式用 `auto`（瞬时）；按钮/发送用 `smooth`
- 用 `requestAnimationFrame` 节流同一帧内的多次调用

### 2. 修改 `web/src/hooks/useChat.ts`
- 接收参数新增 `scrollToBottom: (opts?: { force?: boolean }) => void`（替代原 `endRef` 直接驱动滚动；`endRef` 仍保留供锚点用）
- 删除原 `scroll`（`167-170` 行的 setTimeout + smooth scrollIntoView）
- 新增 `scroll` 轻封装：`const scroll = useCallback(() => scrollToBottom(), [scrollToBottom])` —— 流式跟随（仅贴底）
- 所有现有 `scroll()` 调用点保持：
  - `248`（loading/reasoning chunk）—— 仅贴底跟随 ✓
  - `351`（send 用户发消息后）—— 改为 `scrollToBottom({ force: true })` 强制贴底（用户刚发消息，理应跟随）
- 在 `finished`（约 `283-301`）和 `error`（约 `302-321`）分支末尾补 `scroll()`（仅贴底跟随，符合"终态仅贴底时跟随"）
- 依赖项更新（`scroll` 的 useCallback deps）

### 3. 修改 `web/src/pages/Chat.tsx`
- 引入 `useStickToBottom`

- 把 `scrollToBottom` 传入 `useChat({ ..., scrollToBottom })`

## 关键实现细节
- **贴底判断**用 `useRef`（`stickRef`）而非 `useState`，因为流式 `doStream` 回调闭包会捕获过期的 `isStuck`，而 `useRef.current` 始终最新。
- **scroll 事件被动监听**：`addEventListener('scroll', handler, { passive: true })`，在 effect cleanup 中 removeEventListener。
- **流式跟随用瞬时滚动**（`scrollTop = scrollHeight` 直接赋值，不走平滑动画），避免高频 chunk 下动画堆叠。
- **不引入第三方库**，纯原生 DOM + React。
- **ESM 规范**：新文件内部 import 用 `.js` 扩展名；跨包用包名。

## 不改动
- `tentacle`（NDJSON 解析）、`MessageList`/`MessageBubble` 渲染结构、流式协议、后端。
- 不引入虚拟滚动库。
