# 修复 server 反复 EADDRINUSE（端口 5050）问题

## 根因（已确认）
1. `server/src/main.ts` 的 `serve({ fetch, port })` **没传 `hostname`**，默认绑定到 IPv6 `::`（双栈）。Windows 上 IPv4 (`0.0.0.0:5050`) 与 IPv6 (`[::]:5050`) 是两个独立的监听 socket，杀进程时容易只杀掉一行，造成"杀了还在"的错觉，重启就 EADDRINUSE。
2. `dev` 脚本用 `node --watch dist/main.js`，监听文件变化时会 fork 新子进程；如果 `Ctrl+C` 只杀了 `concurrently` 父进程，实际持有 5050 的子进程可能残留。
3. 日志里硬编码打印 `http://127.0.0.1:${port}`，与实际绑定（`::`）不一致，进一步误导排查。

## 改动（仅改 `server/src/main.ts` 一个文件）

### 1. 显式绑定到 `127.0.0.1`
给 `serve()` 加 `hostname: "127.0.0.1"`，这样：
- 只绑定 IPv4 loopback，不再有 IPv6/IPv4 双 socket 的歧义；
- 日志里的 `127.0.0.1` 与实际绑定一致；
- dev 环境下 server 只对本机可见（web 通过 Vite proxy 走 `127.0.0.1:5050`，完全够用）。

如果未来需要对外暴露，可以读 `OCTOPUS_HOST` 环境变量覆盖，默认仍是 `127.0.0.1`。

### 2. 启动失败时给出可操作的提示
在 `serve()` 外层包一个对 `process` 的 `uncaughtException`/`unhandledRejection` 局部处理，或在 `serve()` 同步抛出后用 try/catch 捕获 `EADDRINUSE`，打印一行中文提示，告诉用户：
- 端口被占用，给出 `netstat -ano | findstr :5050` 和 `taskkill /PID <pid> /F` 命令样例；
- 提示可能是 `node --watch` 残留的子进程，建议关闭终端或在任务管理器结束所有 `node.exe`。

这样下次遇到 EADDRINUSE 时，错误信息直接告诉用户怎么处理，而不是只甩一个 Node 原生堆栈。

### 3. （可选小优化）端口已占用检测
启动前用 `net.createServer().listen(port)` 试探一下，若失败直接走上面的中文提示退出，避免打印整段 Node 堆栈。这条优先级较低，可作为可选实现。

## 不做的事
- 不改 `dev` 脚本结构（`node --watch` 本身没问题，问题在绑定地址）。
- 不改端口号默认值（保持 5050）。
- 不引入新依赖。

## 验证
1. 在 `server/` 目录运行 `npm run lint`（即 `tsc --noEmit`）确认类型无误。
2. 手动验证：先正常启动一次 server，确认日志显示 `Listening on http://127.0.0.1:5050`；再用 `netstat -ano | findstr :5050` 确认只有 `0.0.0.0:5050` 或 `127.0.0.1:5050` 一行（不再有 `[::]:5050`）。
3. 模拟占用场景：起一个占用 5050 的进程再启动 server，确认打印的是中文友好提示而非裸堆栈。

## 附：当前快速自救（无需改代码）
在终端运行，杀掉所有占用 5050 的进程（PowerShell，会同时清理 IPv4/IPv6 占用）：
```powershell
Get-Process -Id (Get-NetTCPConnection -LocalPort 5050).OwningProcess -ErrorAction SilentlyContinue | Stop-Process -Force
```
然后再 `netstat -ano | findstr :5050` 确认无输出，重启 server。
