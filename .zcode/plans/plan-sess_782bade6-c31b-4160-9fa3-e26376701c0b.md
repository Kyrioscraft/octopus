## 最终方案：斜杠命令菜单 — 纯鼠标操作 + 清理坏的键盘拦截

### 背景问题
当前 `SlashCommandMenu` 底部显示 `↑↓ 导航 / ↵ 选择 / Esc 关闭` 提示，但这三个快捷键**全部不工作**：
- ↑/↓ 被转发到 `useChat.onKey`，而 `onKey` 完全忽略箭头键 → 光标只是在 textarea 里上下跳
- Enter 被 `InputBar.handleKeyDown` 无条件 `preventDefault()` 吞掉 → 菜单打开时**无法发送消息**，且没有键盘路径能关闭菜单，用户被"卡住"
- Esc 同样被忽略 → 只能靠鼠标或删除 `/` 字符才能关闭

用户已确认走**纯鼠标操作**路线：去掉提示，并删除那套坏的键盘拦截。

### 改动范围（2 个文件）

#### 1. `web/src/components/chat/input/SlashCommandMenu.tsx`

**删除：**
- 底部快捷键提示 footer（lines 130-145 的 `<div>` 含 `↑↓ 导航 / ↵ 选择 / Esc 关闭`）
- 未使用的 `CATEGORY_LABELS` 常量（lines 15-21）
- 未使用的 `handleSelect` useCallback 包装（lines 67-72，直接用 `onSelect` 即可）
- 未使用的 `flatList` 变量（line 77）
- `onClose` prop（lines 28, 36）—— 死代码，从未被键盘路径调用

**保留：**
- `activeIndex` 状态 + `onMouseEnter` hover 高亮（鼠标交互需要）
- `scrollIntoView` 逻辑（鼠标 hover 滚动仍可能用到，保留无害）
- 所有分组渲染、样式、ARIA role

**修复 correctness bug：**
- `useEffect` 重置 `activeIndex` 的依赖从 `[totalCount]` 改为 `[query, commands]`，避免过滤后长度不变时索引指向错误项

**用 `useMemo` 优化：**
- `filtered` / `systemCmds` / `promptCmds` 用 `useMemo` 包裹，依赖 `[commands, query]`，避免每次渲染重算

**Props 签名变更：**
```typescript
export interface SlashCommandMenuProps {
  commands: SlashCommandEntry[];
  query: string;
  visible: boolean;
  onSelect: (cmd: SlashCommandEntry) => void;
  // onClose 删除
}
```

#### 2. `web/src/components/chat/input/InputBar.tsx`

**简化 `handleKeyDown`（lines 130-152）：**
- 删除 `slashMenuVisible` 分支里对 ArrowUp/Down/Escape 的转发逻辑
- 删除菜单打开时对 Enter 的无条件 `preventDefault()` 拦截
- 简化为：直接调用 `onKey(e)`，让 Enter 照常发送（用户在 `/` 菜单打开时按 Enter = 发送当前 `/xxx` 文本，符合预期；要选命令就用鼠标）

简化后：
```typescript
const handleKeyDown = useCallback(
  (e: React.KeyboardEvent) => {
    onKey(e);
  },
  [onKey],
);
```
（如果只剩这一行，可以直接把 `onKey` 传给 TextArea 的 `onKeyDown`，删除 `handleKeyDown` 包装；但为保持改动最小、保留扩展点，保留包装也可。最终以代码清晰度决定。）

**更新 `SlashCommandMenu` 调用（lines 165-171）：**
- 删除 `onClose={handleSlashClose}` prop 传递
- `handleSlashClose` 函数（lines 124-127）若不再被其他地方引用则一并删除（确认仅此处使用 → 删除）

### 不改动
- `useChat.ts` 的 `onKey`（Enter 发送 / Shift+Tab 切换模式）—— 已经正确，无需改
- `Sidebar.tsx`、`Chat.tsx`、`useChat.ts` 的其他部分 —— 不涉及
- 后端、core、tentacle —— 不涉及

### 验证
- `cd web && npx tsc --noEmit` 通过
- 手动验证（开发时）：输入 `/` 弹出菜单 → 鼠标 hover 高亮正常 → 点击选中正常 → 输入空格菜单关闭 → 删除 `/` 菜单关闭 → 菜单打开时按 Enter 能正常发送（不再被吞）

### 行为变化总结
| 场景 | 改动前 | 改动后 |
|------|--------|--------|
| 菜单打开时按 ↑/↓ | 光标在 textarea 跳，高亮不动 | 光标在 textarea 跳（无影响，纯鼠标操作） |
| 菜单打开时按 Enter | **被吞，无法发送**（bug） | 正常发送当前文本 |
| 菜单打开时按 Esc | 无反应 | 无反应（用鼠标点击外部或删除 `/` 关闭） |
| 底部快捷键提示 | 显示假的 ↑↓↵Esc | 不显示 |
| 过滤后长度不变时高亮 | 可能指向错误项 | 正确重置到首项 |
