# TUI 启动体验修复方案

## 问题根因总结

经代码探查，四个问题的根因如下：

| # | 问题 | 根因 | 关键位置 |
|---|------|------|---------|
| 1 | 启动不清屏 | `render()` 调用时未做任何清屏，也未用全屏模式 | `tui/src/cli.ts:180` |
| 2 | 无"正在连接"欢迎页 | 服务器在 Ink 渲染**之前**同步启动完毕（`await sm.start()`），到 `App` 挂载时健康检查秒过，`connecting` 阶段一闪而过 | `tui/src/cli.ts:146-150` |
| 3 | 不显示历史聊天 | `loadThreadHistory` 只填充 `messages`，但默认渲染路径 `useBlockRendering=true` 读取的是 `sessionState.turns`（始终为空） | `app.tsx:66`、`main-screen.tsx:122-146`、`use-chat-session.ts:449-459` |
| 4 | 上键无历史输入 | ① 上键判定要求 `cursorPos===0`（易失效）；② 空输入+上键被 mouse-wheel 早退逻辑吞掉（`chat-input.tsx:202`）；③ 补全弹窗打开时上键被拦截；④ 历史不持久化，重启即丢 | `tui/src/components/chat-input.tsx:202,209-215,289-296` |

## 修复方案（逐项）

### 修复 1：启动清屏

**文件：`tui/src/cli.ts`**

在 `render(createElement(App, appProps), {...})` 调用**之前**，向 stdout 写入清屏转义序列：

```ts
// 清屏 + 清回滚缓冲 + 光标归位（在 Ink 渲染前执行，避免闪烁）
process.stdout.write("\x1b[2J\x1b[3J\x1b[H");
```

- `\x1b[2J` — 清当前屏幕
- `\x1b[3J` — 清回滚缓冲（彻底清掉历史显示，符合用户"清掉当前命令行窗口的历史显示"的诉求）
- `\x1b[H` — 光标归位

仍保留 `alternateScreen: OFF`（不加 `fullscreen`），这样 Ink 继续在普通屏幕缓冲区渲染，用户仍可滚动查看 Ink 写入的回滚内容（符合现有注释的设计意图）。

### 修复 2：显示"正在连接服务"欢迎页

**核心改动：把服务器启动从"渲染前同步阻塞"改为"渲染后异步进行"。**

**文件：`tui/src/cli.ts`（`runInteractive`）**

1. 去掉 `await sm.start()`（146-150 行），改为把 `ServerManager` 实例传入 `App`，让 App 在 `useEffect` 中触发启动。
2. 这样 App 挂载时初始 `phase="connecting"`，`ConnectingScreen` 会持续显示（带 spinner 动画），直到服务器就绪。

**文件：`tui/src/app.tsx`**

1. `AppProps` 新增可选字段 `serverManager?: ServerManager`（类型从 `./client/server-manager.js` 导入）。
2. 在挂载 `useEffect` 中：若 `serverManager` 存在，先 `await sm.start()`，若失败则设置 `initialError` 并跳到 `startup_error`；成功则继续 `connection.initializeConnection(...)`。
3. 在 `finally`/卸载逻辑中调用 `sm.stop()`（保持原有的"退出即停服务器"行为）——通过把 `waitUntilExit` 退出后的 `sm.stop()` 移到 `App` 的卸载 effect，或保留在 cli.ts 的 `finally`（因为 `await waitUntilExit()` 仍阻塞在 cli.ts）。

> 具体实现：`ServerManager` 实例通过 props 传入 App；App 的 `useEffect` 负责调 `start()`。`cli.ts` 的 `finally { await sm.stop() }` 不变（仍兜底确保进程退出时清理）。

**文件：`tui/src/hooks/use-server-connection.ts`**

无需大改。`initializeConnection` 已是 `connecting → ready|startup_error` 的流程，只要服务器不在渲染前就被启动，`ConnectingScreen` 就能正常显示。

### 修复 3：启动显示工作区历史聊天

**核心思路：让 `loadThreadHistory` 在加载 `messages` 的同时，把历史消息也重建为 `SessionState.turns`，这样 `useBlockRendering=true` 的路径也能渲染。**

**文件：`tui/src/hooks/use-chat-session.ts`**

新增辅助函数 `messagesToTurns(rows)`：将 `MessageRow[]` 转换为 `Turn[]`：
- 每条 `user` 消息 → 一个 `user` turn，含一个 `text` block
- 每条 `assistant` 消息 → 一个 `assistant` turn，含一个 `text` block（若有 `toolCalls` 则附加 `tool_call` block）
- `tool`/其他角色消息 → 归入前一个 assistant turn（或单独处理）

修改 `loadThreadHistory`（449-459 行）：
```ts
const loadThreadHistory = useCallback(async (threadId: string): Promise<void> => {
  const client = clientRef.current;
  if (!client) return;
  try {
    const { history } = await client.getThreadHistory(threadId);
    setCurrentThreadId(threadId);
    setMessages(history.map(rowToMessage));
    // 新增：重建 block-level turns，供 ChatRenderer 渲染
    const turns = messagesToTurns(history);
    setSessionState({ turns, pendingConfirm: null });
  } catch (err) {
    logger.exception(`Failed to load history for thread ${threadId}`, err);
  }
}, [rowToMessage]);
```

**文件：`tui/src/hooks/use-chat-session.ts`（`executeMessageAsBlocks` 开头）**

当前每次发消息时 `setSessionState` 是**追加** turn（`...prev.turns`）。加载历史后再发新消息不会有问题（追加在历史 turns 之后）。但需确认：若用户在历史会话里继续聊天，`client.streamChat` 传的是 `threadRef.current`（已由 `loadThreadHistory` 的 `setCurrentThreadId` 设好），服务器会用同一 thread 续聊 —— 符合预期。

### 修复 4：输入框上键回溯历史

**文件：`tui/src/components/chat-input.tsx`**

#### 4a. 放宽上键判定条件（289 行）

```ts
// 改前：if (key.upArrow && cursorPos === 0)
// 改后：if (key.upArrow && !showCompletions)   // 只要没开补全弹窗就允许
```

同理放宽下键（299 行）：`if (key.downArrow && !showCompletions)`。

`InputHistory` 内部已处理边界（到底/到顶返回当前值），无需 `cursorPos` 判定。

#### 4b. 修复 mouse-wheel 早退逻辑误吞真上键（202 行）

当前代码 `if (input === "" && (key.upArrow || key.downArrow)) return;` 在某些终端（含 Git Bash/mintty）会吞掉真正的上键事件。改为：**仅当历史为空时才跳过**（保留对纯 wheel 事件的忽略，但不误伤有历史时的导航）：

```ts
// 改后：只有当历史为空时，才把"空输入+方向键"当作 wheel 事件忽略
if (input === "" && (key.upArrow || key.downArrow) && historyRef.current.size === 0) return;
```

需给 `InputHistory` 加一个 `get size()` 取值器。

#### 4c. 持久化输入历史到磁盘

新增轻量持久化模块 `tui/src/utils/input-history-store.ts`：
- 路径：`~/.deepagents/.state/tui-input-history.json`
- `load(): string[]` — 启动时读取（限制 1000 条）
- `append(entry: string): void` — 追加并去重、异步落盘（debounce）

在 `ChatInput` 组件：
- 初始化 `historyRef` 时 `new InputHistory(loadHistory())`（让 `InputHistory` 构造器接受初始数组）
- `historyRef.current.add(value)` 后调用持久化的 append

> 考虑到本次修复聚焦"启动体验"，持久化作为 4c 子项一并实现，让上键回溯真正跨会话可用（与用户"输入框向上键可以选择历史输入"的期望一致）。
