# 修复 TUI 中 ask_user_question 工具不生效的问题

## 问题根因

服务器对三种 HITL 场景统一发送 `ask_user_question_required` 状态，通过顶层 `kind` 字段区分：
- `tool_approval` — 工具调用审批（被动触发）
- `discussion` — Agent 主动调用 ask_user_question 工具（带选项）
- `clarify` — Agent 主动调用该工具（纯文本回答）

**TUI 的 bug：** 流处理器 `tui-adapter.ts:395` **完全忽略了 `kind` 字段**，把所有事件都当成 tool_approval 处理。因此当 Agent 调用 ask_user_question 工具时：
1. discussion/clarify 问题被错误地路由到 `onApprovalRequired`
2. 由于 `actionRequests` 为空，显示为 "未知操作" 的审批菜单
3. `requestAskUser` 回调是死代码 stub（恒返回 cancelled）
4. 已写好的 `AskUserMenu` 组件**从未被任何模块 import**
5. resume 请求只构造 `tool_approval` 格式，无法回传 answers
6. TUI 本地类型 `Question`（无 `question_id`）与网络类型 `AskQuestion` 不匹配

## 实施方案

### 第 1 步：更新 TUI 类型定义 (`tui/src/types.ts`)
- 扩展本地 `Question` 类型以匹配网络协议 `AskQuestion`，新增字段：
  - `question_id: string`（答案配对的关键键）
  - `header?: string`
  - `options?: Array<{ label: string; value: string; description?: string }>`（替代现有 `choices`，保持向后兼容）
  - `multi_select?: boolean`
  - `allow_other?: boolean`
  - `kind?: AskKind`（在 `AskUserRequest` 上记录来源 kind）
- 更新 `AskUserAnswered` 的 answers 结构，改为 `Array<{ question_id: string; selection?: string | string[]; text?: string }>` 以匹配 `ResumeRequestBody.answers`

### 第 2 步：在流处理器分流 kind (`tui/src/tui-adapter.ts:395-406`)
```ts
case "ask_user_question_required": {
  callbacks.setSpinner(null);
  const kind = (event.kind ?? "tool_approval") as AskKind;
  const questions = (event.questions as AskQuestion[]) ?? [];
  if (kind === "tool_approval") {
    const actionRequests = (event.actionRequests as unknown[])
      ?? (event.meta?.interrupt?.actionRequests as unknown[]) ?? [];
    callbacks.onApprovalRequired(questions, actionRequests);
  } else {
    // discussion / clarify — agent 主动提问
    callbacks.onAskUserRequired(questions, kind);
  }
  break;
}
```
同时在 `TuiAdapterCallbacks` 接口中新增 `onAskUserRequired(questions, kind)` 回调（保留 `requestAskUser` 不动，但用新回调替代死 stub 的职责）。

### 第 3 步：实现 ask-user 状态与 resume (`tui/src/hooks/use-chat-session.ts`)
- 新增状态 `pendingAskUser: { questions: AskQuestion[]; kind: AskKind } | null`
- 实现 `onAskUserRequired` 回调：设置 `pendingAskUser` + `setPhase("blocked")`
- 新增 `handleAskUserAnswer(result)` 处理函数：
  ```ts
  const resumeBody: ResumeRequestBody = {
    kind: pendingAskUser.kind,            // "discussion" | "clarify"
    answers: pendingAskUser.questions.map((q, i) => ({
      question_id: q.question_id,
      selection: Array.isArray(result.answers[i]) ? result.answers[i] : result.answers[i],
      text: (allow_other 且选了 Other) ? result.answers[i] : undefined,
    })),
  };
  await resumeAgentTask(ctx, resumeBody);
  ```
- 取消（Esc）时：构造 `reject` 风格的回复让 Agent 继续而不挂起
- 在 `UseChatSessionReturn` 暴露 `pendingAskUser` 和 `handleAskUserAnswer`
- 清理现有 `requestAskUser` stub（保留接口字段或标记 deprecated）

### 第 4 步：渲染 AskUserMenu (`tui/src/components/screens/main-screen.tsx:118-126`)
在 `pendingApproval` 渲染分支旁，新增并列分支：
```tsx
{pendingAskUser && (
  <AskUserMenu
    questions={adaptQuestions(pendingAskUser.questions)}
    onAnswer={onAskUserAnswer}
  />
)}
```
其中 `adaptQuestions` 将网络 `AskQuestion`（options/allow_other）映射为 `AskUserMenu` 期望的本地 `Question[]`（choices/type），并透传 `question_id`。

### 第 5 步：更新 `AskUserMenu` 组件 (`tui/src/components/ask-user.tsx`)
- 读取 `question.options` 优先于 `question.choices`（向后兼容）
- 让 `onAnswer` 回传结构化 answers（带 `question_id`），而非简单 `string[]`
- 支持 `multi_select`（多选）
- 保持现有的 ↑↓ 导航、Enter 选择、Other 自由输入、Esc 取消交互

### 第 6 步：更新 app.tsx / 主屏幕 props 透传
- 将 `pendingAskUser`、`handleAskUserAnswer` 从 `useChatSession` 透传到 `MainScreen`
- MainScreen 的 props 接口扩展

## 受影响文件
| 文件 | 改动 |
|---|---|
| `tui/src/types.ts` | 扩展 Question/AskUserAnswered 类型 |
| `tui/src/tui-adapter.ts` | 分流 kind，新增 onAskUserRequired 回调 |
| `tui/src/hooks/use-chat-session.ts` | 实现 pendingAskUser 状态 + handleAskUserAnswer resume |
| `tui/src/components/ask-user.tsx` | 适配新类型，支持 options/multi_select，回传结构化答案 |
| `tui/src/components/screens/main-screen.tsx` | 渲染 AskUserMenu 分支，透传 props |
| 可能的 `tui/src/app.tsx` 或上层组件 | 透传 pendingAskUser/handler 到 MainScreen |

## 验证方式
- `cd tui && npm run lint`（即 `tsc --noEmit`）确保类型正确
- 手动测试：让 Agent 调用 ask_user_question 工具，验证弹出 AskUserMenu 而非 "未知操作" 审批菜单
- 测试 discussion（带选项）、clarify（纯文本）、Other 自由输入、Esc 取消、多问题流程
- 测试 resume 后 Agent 正确收到答案并继续

## 注意事项
- 不改动 server/core/tentacle —— 它们已正确实现，仅 TUI 端缺失
- resume 的 answers 数组长度必须与 questions 一致，且 `question_id` 配对正确
- Esc 取消需构造合法 resume（不能直接挂起 Agent），策略：发送空选/取消文本让 Agent 感知用户放弃
- 保持现有 tool_approval 流程完全不动
