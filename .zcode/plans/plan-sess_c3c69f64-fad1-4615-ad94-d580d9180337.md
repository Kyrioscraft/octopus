## 根因

`/clear` 命令在**状态层完全正常**：`dispatch.ts:97-105` 正确调用了 `setMessages([])`、`setCurrentThreadId(null)`、`setMessageQueue([])`、`setPhase("ready")` 等，React state 确实被清空了。

问题出在**渲染/终端层**：

1. Ink 的 `<Static>` 组件是 **append-only（只追加）**。一旦消息被 `<Static>` 渲染，Ink 就把这些行**直接写入 `process.stdout`**，并从 React 树中丢弃——这些字节已经物理地落到了终端的 scrollback buffer 里。
2. `messages.tsx:552` 的 `genRef`/`staticKey` 技巧只会在 React 层 **remount（重新挂载）** `<Static>` 组件，它**不会擦除已经写到 stdout 的那些行**。换 key 只强制一次全新渲染，无法回滚已打印的字节。
3. 因此 `/clear` 后：React state 是 `["Chat cleared..."]`（1 条），但屏幕上**旧的滚动内容仍然可见**——用户看到"没生效"。

## 修复方案

实现真正的终端清屏（`\x1b[2J\x1b[3J\x1b[H`：清屏 + 清 scrollback + 光标归位），与 claude/codex 等主流 TUI 的 `/clear` 行为一致。状态清理逻辑保持不动。

### 改动 1：`tui/src/commands/dispatch.ts`

1. 在 `DispatchDeps` 接口（约 18-56 行）新增一个字段：
   ```ts
   /** Clear the terminal screen + scrollback (for /clear, /force-clear). */
   clearTerminal: () => void;
   ```

2. 在解构（约 64-71 行）中加上 `clearTerminal`。

3. 在 `case "clear":`（97-105 行）和 name-based fallback 的 `case "/clear":` `case "/force-clear":`（162-171 行）中，**在 `setMessages([])` 之前**调用 `clearTerminal()`：
   ```ts
   case "clear":
     clearTerminal();
     setMessages([]);
     // ... 其余保持不变
   ```

   先清屏再清 state，确保 `<Static>` 重新挂载时是空的、不会把旧内容再次 flush。

### 改动 2：`tui/src/app.tsx`（注入 clearTerminal）

在 `createDispatchCommand({...})` 调用处（约 163-182 行）新增依赖：
```ts
clearTerminal: () => {
  // ESC[2J — clear visible screen
  // ESC[3J — clear scrollback buffer (xterm / Windows Terminal / iTerm2 支持)
  // ESC[H  — cursor to home
  process.stdout.write("\x1b[2J\x1b[3J\x1b[1;1H");
},
```

> 直接用 `process.stdout.write`，无需 `useStdout`（`dispatch` 是 hook 外的普通函数，不在 React 渲染上下文里；`process.stdout` 在 Ink TUI 进程里就是它正在写的同一个 stdout，与 `<Static>` 输出目标一致）。

### 改动 3（可选、清理）：`tui/src/components/messages.tsx`

`genRef`/`staticKey` 的 remount 技巧（546-596 行）原本是为了缓解"清不掉屏幕"的问题。在加了真正的终端清屏后它依然有用（保证 `<Static>` 内部 state 重置，避免下次渲染时把残余项目再 flush），所以**保留**。只是更新注释，说明真正的清屏由 dispatch 里的 `clearTerminal()` 负责、这里只负责 React 侧的 state 重置（不改逻辑，避免引入回归）。

## 验证

- `cd tui && npx tsc --noEmit` 通过类型检查（仓库无 test runner，AGENTS.md 明确要求用 `tsc --noEmit` 验证）。
- 手动启动 TUI（`oc` 或 `cd tui && npm run dev` 对应的入口），发几条消息让 `<Static>` 有输出后输入 `/clear`，确认：
  - 屏幕与 scrollback 都被清空；
  - 只剩 "Chat cleared..." 提示；
  - 下一条消息会创建新 thread（`setCurrentThreadId(null)` 已生效）。
- 额外验证 `/force-clear` 走 fallback 分支也能清屏。

## 风险与边界

- `\x1b[3J`（清 scrollback）在极简终端（如老版 cmd.exe、某些 CI 的非 TTY）可能不支持，但 `runInteractive` 在 `cli.ts:125` 已要求 `process.stdin.isTTY`，且注释里明确推荐 Windows Terminal / mintty，覆盖范围内都支持。不支持时 `\x1b[2J` + `\x1b[H` 仍能清可见区域，不会出错。
- 清屏是 `process.stdout.write`，与 Ink 的 `incrementalRendering` 不冲突——Ink 会在下一帧把当前 React 树（只剩 1 条确认消息）重新 diff 渲染到已清空的屏幕上。
- 不动 server / core / tentacle，符合架构边界（纯 TUI 内部行为）。
