# 探索约束 + 读取效率优化（学习 ZCode 的方式）

## 背景

trace 显示模型读了 11+ 个文件才动手优化，远超用户期望的"3 次以内"。
之前加的"Exploration Discipline"prompt 段落是纯文字约束，太弱。
用户要求结合两个方向（prompt 精简 + 运行时约束），并按 ZCode 的方式处理。

## ZCode 的探索控制方式（分析结论）

ZCode **不做硬拦截**，它靠 4 个机制让模型自然少读：
1. **Grep 默认 `files_with_matches`**（只返回路径，快速定位）
2. **Read 默认读全文件**（2000 行，一次读完不分页）
3. **重复读检测**：Read 工具内置 `"Wasted call — file unchanged since your last Read"` 运行时提示
4. **microcompaction**：旧工具结果自动清除（本次不做）

octopus 已具备 2（prompt 已删分页指导），但缺 1 和 3。

## 改动（3 个文件）

### 改动 1：精简 prompt，删冗长段落，留精炼约束
**文件**：`packages/core/src/prompts.ts`

- **删除**整个"Exploration Discipline — read with purpose, stop when you know enough"段落（128-156 行，约 30 行）——这段太长、纯文字、模型不执行
- **替换**为一段精炼的 3 行约束，放在"Codebase Search"段末尾：
  ```
  Rule: explore with a budget. After `ls` + reading 2-3 core files, ACT —
  don't read the whole project. Skip low-signal files (`__init__.py`,
  entry stubs, config boilerplate) unless the task targets them.
  ```
- **保留**现有的 grep_search 引导、glob 引导、并行引导（这些有效）

### 改动 2：新增 ReadBudgetMiddleware — 运行时重复读检测（ZCode 核心机制）
**文件**：`packages/core/src/middleware/read_budget_middleware.ts`（新建）

**机制**（照搬 ZCode 的 "Wasted call" 模式，扩展为"读取预算"）：
- 在 `wrapModelCall` 里扫描 `request.messages`
- 统计**唯一的 read_file 路径**（按 file_path 去重，同一文件多次读只算 1 次）
- 在每次 model call 时，如果发现以下情况，在 system message 末尾追加一条**运行时提醒**：
  - **重复读同一文件**：`"[hint] You already read {path} — refer to that earlier result instead of re-reading."`（ZCode 的 "Wasted call" 机制）
  - **读取超过 4 个唯一文件但尚未做任何 edit_file/write_file/execute**：`"[hint] You've read {N} files without making changes. Consider acting now or using grep_search for targeted lookups."`

**关键设计**：
- **纯提示，不阻止读取**——模型仍能读，但会看到提醒
- **无状态持久化**——每次 wrapModelCall 都基于 `request.messages` 重新计算，天然幂等、无 thread 隔离问题
- **幂等**——提醒文本追加到 system message，不会因为重复追加而堆积（检查是否已存在）
- **阈值 4**（可配置）——用户期望 3 次以内，给 1 次缓冲

**实现模板**（参考 `filesystem_policy_middleware.ts` 的 wrapModelCall 结构）：
```ts
class ReadBudgetMiddleware {
  name = "ReadBudgetMiddleware";
  
  wrapModelCall = (request, handler) => {
    const messages = request.messages ?? [];
    
    // 1. 扫描所有 ToolMessage，提取 read_file 的路径 + 时间顺序
    // 2. 扫描所有 AIMessage 的 tool_calls，找 edit_file/write_file/execute（判断是否已"动手"）
    const readPaths = extractReadPaths(messages);  // Set<string>，去重
    const hasActed = checkHasActed(messages);      // boolean
    
    // 3. 找最近一次 read_file，检查是否重复读
    const lastRead = findLastReadCall(messages);
    const isReRead = lastRead && readPaths.size > 1 && 
                      readPaths.has(lastRead.path);  // 之前读过，现在又读
    
    // 4. 生成提醒
    let hint = "";
    if (isReRead) {
      hint = `[hint] You already read ${lastRead.path} earlier. Refer to that result instead of re-reading.`;
    } else if (readPaths.size >= 4 && !hasActed) {
      hint = `[hint] You've read ${readPaths.size} files without making changes. Consider acting now or using grep_search for targeted lookups.`;
    }
    
    if (!hint) return handler(request);
    
    // 5. 追加到 system message（幂等：检查是否已包含 hint）
    // 复用 filesystem_policy_middleware.ts 的 systemMessage 重写模式
    return handler(appendHintToSystemMessage(request, hint));
  };
}
```

### 改动 3：注册 ReadBudgetMiddleware
**文件**：`packages/core/src/agent.ts`（~640 行，middleware 栈）

- 在 `FilesystemPolicyMiddleware` 之后、`LocalContextMiddleware` 之前 push：

## 不做的（明确排除）

- ❌ **硬拦截读取**（ZCode 不做，用户体验差）
- ❌ **缓存优化 / stable-dynamic 分段**（本次范围外，用户明确说只做探索约束）
- ❌ **microcompaction**（旧工具结果清除，复杂度高，后续）
- ❌ **stateSchema 持久化计数**（用 messages 扫描更简单、幂等、无隔离问题）
