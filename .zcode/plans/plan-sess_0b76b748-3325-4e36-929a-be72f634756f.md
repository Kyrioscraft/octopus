# 重新定义对话标题生成时机

## 问题
当前标题生成条件（`server/src/services/chat.service.ts:568`）：
```ts
if (input.isNewThread && !hasInterrupt && input.modelSpec)
```
只要新会话首回合触发 HITL 工具审批（`hasInterrupt=true`），标题就被跳过；而 `streamResume`（617-706 行）完全没有标题逻辑，后续回合 `isNewThread` 已为 false——导致**标题永久停留在"新对话"**。

## 目标行为
- **首回合发消息时（`streamChat` 入口）**：只要 `isNewThread && modelSpec` 就生成标题，**与是否中断无关**。即使本回合被 HITL 中断，标题也立即写入 DB。
- **resume 路径**：不动（它不是新回合入口，首回合已生成标题）。
- **后续新消息**：`isNewThread=false`，不再生成（尊重用户手动改名）。
- 输入：始终用第一条用户消息（即 `input.userMessage`，因为首回合就是第一条）。
- 兜底：LLM 失败 → 取 `input.userMessage.slice(0, 30)`。

## 为什么不需要新增 DB 列或改前端
1. `streamChat` 的 `ChatInput` 已包含 `userMessage` + `modelSpec` + `isNewThread`，生成所需信息齐全。
2. 首回合 = 第一条用户消息，所以 `input.userMessage` 天然就是"首条消息"，无需从 DB 反查。
3. `meta.title` 是死字段（前端 `useChat.ts:267-285` 不读它），前端靠 `listThreads()` 刷新拿标题——只要把标题写进 DB，前端侧边栏自然显示。中断场景下前端虽不触发 listThreads（finished 不 emit），但用户在侧边栏切换/重进时会刷新；若希望更及时，可在 `init` 分支也刷新（前端已是这样：`useChat.ts:201` 新线程 init 会调 listThreads）。

## 改动点（仅 1 个文件）

### `server/src/services/chat.service.ts` (566-580 行)
把标题生成从 `!hasInterrupt` 条件中解耦：标题生成只依赖 `isNewThread && modelSpec`；`finished` 的 emit 仍受 `!hasInterrupt` 控制（中断时不 emit finished，这是正确的——回合未结束）。

**修改前：**
```ts
// 5. Auto-generate title BEFORE finished so it rides in meta.title.
let newTitle: string | undefined;
if (input.isNewThread && !hasInterrupt && input.modelSpec) {
  try {
    const generated = await generateTitle(input.userMessage, input.modelSpec);
    newTitle = generated ?? input.userMessage.slice(0, 30);
    const { renameThread } = await import("./thread.service.js");
    renameThread(input.threadId, newTitle);
    logger.info(`Auto-titled thread ${input.threadId}: "${newTitle}"`);
  } catch (err) {
    logger.exception("Auto title generation failed", err);
  }
}

// 6. Emit finished (with title for new threads).
if (!hasInterrupt) {
  emit({
    status: "finished",
    meta: {
      thread_id: input.threadId,
      ...(newTitle ? { title: newTitle } : {}),
    },
  });
}
```

**修改后：**
```ts
// 5. Auto-generate title for a new thread's first turn. This is independent
//    of HITL interrupts: even if the first turn pauses on a tool approval,
//    the title is generated now (from the user's first message) so the
//    sidebar never lingers on "新对话". The finished chunk below still
//    respects hasInterrupt — an interrupted turn isn't actually finished —
//    but the DB title is updated regardless, and the sidebar picks it up on
//    the next listThreads() refresh (triggered by init on re-entry, or when
//    the user navigates the sidebar).
let newTitle: string | undefined;
if (input.isNewThread && input.modelSpec) {
  try {
    const generated = await generateTitle(input.userMessage, input.modelSpec);
    newTitle = generated ?? input.userMessage.slice(0, 30);
    const { renameThread } = await import("./thread.service.js");
    renameThread(input.threadId, newTitle);
    logger.info(`Auto-titled thread ${input.threadId}: "${newTitle}"`);
  } catch (err) {
    logger.exception("Auto title generation failed", err);
  }
}

// 6. Emit finished (with title for new threads). Interrupted turns don't emit
//    finished — the turn isn't done — but the title is already persisted above.
if (!hasInterrupt) {
  emit({
    status: "finished",
    meta: {
      thread_id: input.threadId,
      ...(newTitle ? { title: newTitle } : {}),
    },
  });
}
```

**唯一实质改动**：`input.isNewThread && !hasInterrupt && input.modelSpec` → `input.isNewThread && input.modelSpec`（删除 `!hasInterrupt`），并更新注释说明设计意图。

## 验证
- 改动后运行 `cd server && npx tsc --noEmit` 确认无类型错误。
- 行为验证（手动）：
  1. 新会话发一条会触发工具审批的消息（如 confirm 模式下的文件操作）→ 被中断时侧边栏标题应已更新（重新进入或刷新侧边栏可见）。
  2. 新会话发一条普通消息（无中断）→ finished 时标题更新（回归，原有行为不变）。
  3. 老会话发新消息 → 标题不变（不覆盖手动改名）。

## 风险与边界
- **幂等性**：首回合如果被多次中断/恢复，`streamResume` 不生成标题，所以不会重复调用 LLM。只有 `streamChat`（新消息入口）生成一次。
- **clientAborted 场景**（`chat.service.ts:524`）：用户首回合点 stop 中断流时，本改动下标题**仍会生成**（因为不再依赖 `!hasInterrupt`，且 clientAborted 不影响标题生成分支）。这是可接受的——首条消息已存在，生成标题合理；DB 写入成功，前端下次 listThreads 能拿到。
- **不影响 resume 路径**：`streamResume`（617-706 行）完全不变。
