# app.tsx 组件抽象重构方案

## 目标

将 `tui/src/app.tsx`（1323 行，22 个 useState，10 个 useRef，15 个 useCallback）拆分为清晰的模块，解决"改一个功能需要改多处"的问题。

## 核心原则

- **每个功能模块的代码只存在于一个地方**
- **消除 ref mirror 反模式**（6 对 state/ref 同步）
- **消除重复的 Effect Wrapper 模式**（3 个结构完全相同的组件）
- **命令分发逻辑与命令定义合并**，不再是两个 switch 分散在两处

---

## 文件结构变更

```
tui/src/
  app.tsx                              → 精简为 ~80 行编排组件
  hooks/
    use-server-connection.ts           ← 新增：连接生命周期
    use-chat-session.ts                ← 新增：消息/线程/队列管理
    use-approval-flow.ts               ← 新增：HITL 审批流程
    use-modal-manager.ts               ← 新增：模态框状态 + 数据加载
    use-command-registry.ts            ← 新增：斜杠命令注册 + 分发
  components/
    screens/
      connecting-screen.tsx            ← 新增：连接中画面
      error-screen.tsx                 ← 新增：连接失败画面
      main-screen.tsx                  ← 新增：主界面（welcome + 消息 + chrome + 输入 + 状态栏）
      index.ts                         ← 新增
    modals/
      lazy-modal.tsx                   ← 新增：泛型懒加载模态框包装器（替代 3 个 Effect Wrapper）

    (现有组件保持不变)
  commands/
    dispatch.ts                        ← 新增：命令分发逻辑（从 app.tsx 迁出）
```

## 分步实施

### Step 1: 创建 `hooks/use-server-connection.ts`

提取连接相关逻辑，消除 `phaseRef`、`clientRef`、`workspaceIdRef`、`initializeConnectionRef` 等 ref mirror。

**职责**：
- 管理 `phase`、`serverError`
- 持有 `clientRef`、`workspaceIdRef`（作为返回值 ref 暴露给其他 hook）
- 提供 `initializeConnection()`、`reconnect()`

**接口**：
```ts
function useServerConnection(props: {
  serverUrl: string;
  token?: string;
  initialError?: string;
  effectiveModel: string | null;
  setEffectiveModel: (m: string) => void;
}) => {
  phase: AppPhase;
  serverError: string | null;
  clientRef: React.MutableRefObject<TuiClient | null>;
  workspaceIdRef: React.MutableRefObject<string | null>;
  initializeConnection: () => Promise<void>;
};
```

### Step 2: 创建 `hooks/use-chat-session.ts`

提取消息生命周期，消除 `messagesRef`、`threadRef`、`queueRef`、`drainQueueRef` 等 ref mirror。

**职责**：
- 管理 `messages`、`currentThreadId`、`messageQueue`、`spinnerStatus`、`agentCwd`
- 提供 `executeMessage()`、`enqueueOrExecute()`、`drainQueue()`
- 提供 `loadThreadHistory()`、`loadMostRecentThread()`
- 持有 `adapterCallbacks`（TUI adapter → React state 的桥接）
- 提供 `addAppMessage()` 辅助方法

**接口**：
```ts
function useChatSession(deps: {
  clientRef: React.MutableRefObject<TuiClient | null>;
  workspaceIdRef: React.MutableRefObject<string | null>;
  agentName: string;
  autoApprove: boolean;
  phaseRef: React.MutableRefObject<AppPhase>;
}) => {
  messages, currentThreadId, messageQueue, spinnerStatus, agentCwd, inputMode,
  setInputMode, addAppMessage, executeMessage, enqueueOrExecute, drainQueue,
  loadThreadHistory, loadMostRecentThread
};
```

### Step 3: 创建 `hooks/use-approval-flow.ts`

提取 HITL 审批流程，消除 `pendingApprovalRef`、`execContextRef`。

**职责**：
- 管理 `pendingApproval`
- 提供 `handleApprovalDecision()`

### Step 4: 创建 `hooks/use-modal-manager.ts`

统一模态框管理，消除 3 个重复的 load 函数。

**职责**：
- 管理 `activeModal`、`modalModels`、`modalAgents`、`modalMcpServers`、`modalLoading`
- 提供 `openModal(name)`、`closeModal()`
- 提供 `loadModalModels()`、`loadModalAgents()`、`loadModalMcp()`

### Step 5: 创建 `commands/dispatch.ts`

将 `dispatchCommand` 从 app.tsx 迁出，与 `command-registry.ts` 中的命令定义合并到同一个目录。命令处理函数（如退出、清屏、切换模型等）通过一个 handler map 注册，不再用两个 switch 语句。

```ts
// dispatch.ts
export function createDispatchCommand(deps: {
  exit: () => void;
  addAppMessage: (msg: string) => void;
  executeMessage: (text: string, mode: InputMode) => void;
  setActiveModal: (name: string | null) => void;
  setMessages, setCurrentThreadId, setAgentCwd, setMessageQueue,
  setSpinnerStatus, setPhase, setShowTimestamps,
  sessionStats, showTimestamps, commandIndex,
  initializeConnection: () => Promise<void>,
}) {
  return async (cmdName: string, cmdArgs: string): Promise<void> => { ... };
}
```

### Step 6: 创建 `components/screens/connecting-screen.tsx`

纯渲染组件，从 app.tsx 的 `phase === "connecting"` 分支迁出。

### Step 7: 创建 `components/screens/error-screen.tsx`

纯渲染组件，从 app.tsx 的 `phase === "startup_error"` 分支迁出。

### Step 8: 创建 `components/screens/main-screen.tsx`

主界面渲染组件，从 app.tsx 的 `return (<Box flexDirection="column">...` 迁出。

按 props 分组传递，避免 20+ 个独立 prop：
```ts
interface MainScreenProps {
  connection: { phase, effectiveModel, serverUrl };
  chat: { messages, threadId, inputMode, spinnerStatus, cwd, ... };
  modals: { activeModal, modalModels, modalAgents, ... };
  approval: { pendingApproval, onDecide };
  commands: { skills, mergedCommands };
  // ... 少量标量 props
}
```

### Step 9: 创建 `components/modals/lazy-modal.tsx`

泛型懒加载包装器，替代 `ModelSelectorEffect`、`AgentSelectorEffect`、`McpViewerEffect` 三个几乎相同的组件：

```tsx
<LazyModal
  data={modalModels}
  loading={modalLoading}
  loadingText="Loading models..."
  onLoad={loadModalModels}
>
  {(data) => <ModelSelector models={data} ... />}
</LazyModal>
```

### Step 10: 创建 `components/modals/modal-renderer.tsx`

根据 `activeModal` 值渲染对应模态框，替代 app.tsx 中的 7 个 `{activeModal === "xxx" && ...}` 条件块。

### Step 11: 精简 `app.tsx`

最终 app.tsx 只做编排：
```tsx
export const App = (props: AppProps) => {
  const { exit } = useApp();
  const { columns } = useWindowSize();
  const [effectiveModel, setEffectiveModel] = useState(...);
  const [sessionStats, setSessionStats] = useState(...);
  const [showTimestamps, setShowTimestamps] = useState(false);

  const connection = useServerConnection({ ...props, effectiveModel, setEffectiveModel });
  const chat = useChatSession({ clientRef: connection.clientRef, ... });
  const approval = useApprovalFlow({ clientRef: connection.clientRef, addAppMessage: chat.addAppMessage });
  const modals = useModalManager({ clientRef: connection.clientRef });
  const commands = useCommandRegistry({ clientRef: connection.clientRef });

  const dispatch = createDispatchCommand({ exit, ...chat, ...modals, ...commands, ... });
  const submitInput = useCallback((text, mode) => { ... }, [dispatch, chat]);

  // 全局键盘
  useInput((_input, key) => { ... });

  if (connection.phase === "connecting") return <ConnectingScreen ... />;
  if (connection.phase === "startup_error") return <ErrorScreen ... />;
  return <MainScreen connection={...} chat={...} modals={...} approval={...} commands={...} />;
};
```

### Step 12: 清理

- 删除 `AuthManagerEffect`（定义但从未使用）
- 确认所有 import 路径正确（`.js` 后缀）
- 运行 `cd tui && npx tsc --noEmit` 验证类型正确

## 不变更的范围

- 不修改任何子组件（ChatInput、MessageList、StatusBar 等）
- 不修改 tui-adapter.ts、client.ts、command-registry.ts 的对外接口
- 不修改任何行为逻辑，纯结构性重构
- 不做测试（项目当前无测试框架）
