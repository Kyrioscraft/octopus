# 修复工具描述/schema 不匹配 + 强化 system-reminder

## 已完成的排查结论

1. **task 工具无 bug**：SDK schema 就是 `description` + `subagent_type`（L2441：`new HumanMessage({ content: description })`）——`description` 字段即任务提示词。需在描述中消歧义。
2. **execute**：后端 `execute(command)` 只接受 command；timeout 构造时固定 120s、maxOutputBytes=100KB、截断**不落盘**。描述里的 timeout 参数和落盘说明是假的。
3. **read_file**：SDK schema `offset`（0-indexed，default 0）/ `limit`（default 100）被标为 required，默认 100 行过小导致碎片化读取；描述与 schema 矛盾。

## 第一部分：修复描述与 schema 不匹配

### 改动 A：execute 描述如实化（`filesystem_policy_middleware.ts`）
- 删除虚假的 "timeout is in milliseconds (default 120000, max 600000)"
- 改为："Commands time out after 120 seconds (fixed server-side)"
- 删除虚假的"截断落盘"说明，改为：截断即丢失；需要全量输出就重定向到 temp 文件再 read_file 分页；用 `rg --max-count 20`、`git diff --stat` 等控制输出量

### 改动 B：read_file schema + 描述修复（同文件）
- **schema 覆盖**：在 wrapModelCall 工具重写处，用 zod 重建 `read_file` 的 schema：`offset` optional 0-indexed、`limit` optional default 2000、仅 `file_path` required（DynamicStructuredTool 的 `schema` 是 public mutable 属性，与 description 同理）
- 描述同步：去掉"默认 2000 行"与 default 100 的矛盾（覆盖后 default 确实是 2000）；说明 offset 是 0-indexed

### 改动 C：task 描述消歧义（`subagent_orchestration_middleware.ts`）
在 TASK_TOOL_DESCRIPTION 中明确：
- `description` 参数就是完整的任务提示词（self-contained prompt），不是简短标签
- 改写现有 "A new task call starts fresh, so the prompt must be self-contained" 为明确引用字段名的版本

## 第二部分：强化 system-reminder（对齐 ZCode）

**文件**：`dynamic_context_middleware.ts`

### 强化 1：Git 快照（Environment 块内）
构造 reminder 时同步执行（需 async 或构造时预取）：
- `git rev-parse --abbrev-ref HEAD` → 当前分支
- `git status --porcelain` 前 10 行 → 修改文件摘要（超出部分 "… and N more"）
- 失败（非 git 仓库）→ "Is a git repository: no"
- 实现方式：构造函数里用 `child_process.execSync` 一次性预取（图构建时执行一次，不阻塞每次模型调用；分支/状态可能滞后于长会话，但 ZCode 同样是快照式）

### 强化 2：技能列表（Skills 块）
- options 增加 `skills: Array<{name, description}>`（agent.ts 已有 skillsList，含 name/description）
- reminder 中列出：`- name: description`（ZCode 同款），替代现在只给路径
- 超过 15 个截断

### 强化 3：AGENTS.md 内容（可选块）
- 构造时检查 `{cwd}/AGENTS.md` 存在则读取（限 4000 字符），作为独立 reminder 块注入，标注来源
- CLAUDE.md 备选

### 不做：todo 状态注入
- todo 已有 SDK 状态通道（write_todos 工具 + graph state），再加 reminder 会双源不同步
