# TUI 布局重构方案 — 充分利用 Ink v7 yoga-layout

## 背景与问题诊断

当前 TUI 布局建立在一个脆弱的假设之上:`app.tsx:85` 的魔法常量 `MSG_AREA_ESTIMATE = 6`,由此推导 `messageAreaHeight = rows - 6` 作为消息区高度。这个 6 是对 ChatInput 行数的手动估算,但它**完全忽略了**:
- 补全弹窗(最多 +8 行)
- Loading spinner 的 `paddingY`(+2 行)
- ApprovalMenu(变高,可达 10+ 行)
- Welcome 屏的固定 spacer

当这些 chrome 出现时,真实渲染高度与 `messageAreaHeight` 失步,只能靠 `overflow:"hidden"` 兜底裁剪。同时 `messages.tsx` 的 `estimateMessageRows()` 用 `split("\n").length` 猜行数,**忽略终端自动换行和 CJK 双宽字符**,导致滚动几何(thumb/位置/可见 slice)在长行和中文场景下全部失真。

Ink v7.1.0 内置 `yoga-layout@~3.2.1`,并导出 `measureElement(node) => {width, height}`——可在 `useEffect` 后测得 yoga 计算出的真实像素行数(含自动换行)。当前代码**从未调用过它**,只读 `stdout.rows`。这就是重构的杠杆点。

## 核心设计决策(已与用户确认)

1. **滚动**:`measureElement` 精确测量 + **保留虚拟滚动**(只渲染可见 slice,支持长历史)
2. **Body 布局**:三段式 —— 消息区 / 动态 chrome 区 / 输入区
3. **范围**:聚焦核心布局系统(阶段一),~3 文件为主,selectors 暂留

---

## 目标布局树(重构后)

```
<Box flexDirection="column" height={rows}>                    ← Root(仍用 stdout.rows)
  │
  ├─ <BodyRegion>                                             ← flexGrow={1} overflow="hidden"
  │     ref={bodyRef}  ← measureElement 测它,得真实可用高度
  │   │
  │   ├─ <MessageListRegion>                                  ← flexGrow={1} flexDirection="column"
  │   │     ref={msgListRef}                                  ← measureElement 测它,得消息区真实行数 W
  │   │   ├─ <MessageViewport>  height={W} overflow="hidden"   ← 用测得的 W 作为可视窗口
  │   │   │     flexDirection="row"
  │   │   │   ├─ <Content> flexGrow={1} justifyContent="flex-end"  ← 仍 pin 到底部
  │   │   │   └─ <Scrollbar> width={3} flexShrink={0}            ← 仅在溢出时渲染
  │   │   └─ (欢迎屏,空消息时替代上面的 Viewport)
  │   │
  │   └─ <ChromeRegion> flexShrink={0} flexDirection="column"   ← 动态 chrome:自下而上,不再挤占消息区
  │       ├─ {phase==="running" && spinner && <Loading/>}
  │       └─ {pendingApproval && <ApprovalMenu/>}
  │       (Modal/Selector 日后也挂这里,见下文)
  │
  └─ <InputRegion> flexShrink={0} flexDirection="column"        ← 永远钉底,不被压缩
      ref={inputRef}  ← 可选:测它高度做诊断/日志
      └─ <ChatInput/>
</Box>
```

**关键变化**:
- **删除 `MSG_AREA_ESTIMATE` 和 `messageAreaHeight`**。消息区高度不再来自 `rows - 6`,而来自 yoga 在 `MessageListRegion` 上算出的真实 flex 高度。
- **Loading/Approval 从 Body 的平铺兄弟,移到 `ChromeRegion`**(`flexShrink={0}`)。它们出现时,`MessageListRegion`(flexGrow:1)自动收缩,yoga 重排后 `measureElement` 重新测量,`MessageViewport` 的高度随之更新——**无需任何手算常量**。
- **`MessageViewport` 用测得的 `W` 作为 `height`**,代替传入的 `maxHeight` prop。

## 实现步骤

### 步骤 1:新增 `useElementSize` hook(基础设施)

**新文件** `tui/src/components/use-element-size.ts`(~40 行)

封装 `measureElement` 的标准用法,解决它的两个陷阱(渲染期返回 0、内容变化需重测):

```ts
import { useRef, useState, useLayoutEffect, useCallback } from "react";
import { measureElement, type DOMElement } from "ink";

export interface Size { width: number; height: number; }

/**
 * 测量一个 <Box> 的 yoga 计算尺寸。
 * - 返回 ref,挂到目标 <Box>
 * - deps 变化或调用 remeasure() 时,在 useLayoutEffect 后重测
 * - 初始 {0,0},首帧布局完成后填入真实值
 */
export function useElementSize<T extends DOMElement>(deps: unknown[] = []) {
  const ref = useRef<T>(null);
  const [size, setSize] = useState<Size>({ width: 0, height: 0 });

  const measure = useCallback(() => {
    if (ref.current) {
      // Ink 的 measureElement 会读取 yoga 节点的 computed width/height
      setSize(measureElement(ref.current));
    }
  }, []);

  useLayoutEffect(() => {
    measure();
    // deps 改变(如新消息、chrome 显隐、rows 变化)触发重测
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [measure, ...deps]);

  return { ref, size, remeasure: measure };
}
```

**为什么用 `useLayoutEffect`**:要在 Ink 把 yoga 布局算完、DOM 提交后但**浏览器/TTY 刷新前**测量,避免一帧闪烁。Ink 文档明确要求 post-render 调用。

### 步骤 2:重构 `app.tsx` — 三段式 + 删除魔法常量

**改动点**(`app.tsx`):

1. **删除** `MSG_AREA_ESTIMATE`(line 85)和 `messageAreaHeight`(line 86)。
2. **不再** 向 `MessageList` 传 `maxHeight` prop。
3. 引入 `useElementSize` 测量 Body 内 `MessageListRegion`:
   ```tsx
   const { ref: msgListRef, size: msgListSize } = useElementSize(
     [messages.length, phase, spinnerStatus, pendingApproval, rows, activeModal]
   );
   // msgListSize.height 即消息区真实可用行数(已扣除 ChromeRegion 占用)
   ```
   deps 列表覆盖所有会改变 Body 内部高度分布的信号:消息数、phase、spinner、approval、resize、modal。
4. 重构 render 树为三段式(见上方目标树)。`ChromeRegion` 包裹 Loading + ApprovalMenu。Modal placeholder 也挪进 `ChromeRegion`(日后接 selector 时,它们天然占据 chrome 区,不再覆盖消息区)。
5. `MessageList` 改为接收 `viewportHeight={msgListSize.height}`(可为 0,组件内部降级处理)。

**降级保护**:首帧 `msgListSize.height === 0`(measureElement 还没跑),`MessageList` 内部用 `Math.max(8, rows - 8)` 作为初始 fallback,测量到位后自然替换。这保证启动瞬间不会崩。

### 步骤 3:重构 `messages.tsx` — 精确测量取代估算

这是改动最大的文件。两层测量:

#### 3a. 视口高度:用外部传入的 `viewportHeight`(来自 yoga)

```tsx
// 旧:height={maxHeight},maxHeight 来自 rows-6 魔法常量
// 新:height={viewportHeight},viewportHeight 来自 app.tsx 的 measureElement
const constrainHeight = viewportHeight != null && viewportHeight > 0;
```

#### 3b. 单条消息真实行数:用 `measureElement` 缓存

核心难点:虚拟滚动需要知道**每条消息**的行数才能 slice。但 `measureElement` 只能测已渲染的节点。解法:**渲染窗口外的消息用 measureElement 校正缓存**,窗口外的仍用估算兜底。

新增 `useMessageRowCache()` hook(在 `messages.tsx` 内或独立文件):

```tsx
// ref 持有 Map<messageId, measuredRows>
// 每次 render 后,在 useLayoutEffect 中遍历已渲染的 visibleMessages,
// 用 measureElement 测它们的真实 height,写入 cache。
// estimateMessageRows 降级为「未测量过」消息的初值。
const rowCacheRef = useRef<Map<string, number>>(new Map());

useLayoutEffect(() => {
  // 测当前已渲染的每条消息,更新缓存
  itemRefs.current.forEach((node, id) => {
    if (node) rowCacheRef.current.set(id, measureElement(node).height);
  });
}, [visibleMessages]);

const rowsOf = (msg) => rowCacheRef.current.get(msg.id) ?? estimateMessageRows(msg);
```

`computeVisibleRange` 改用 `rowsOf()` 而非 `estimateMessageRows()`。效果:
- **滚动过的消息**用真实行数(含换行、CJK),几何精确。
- **从未滚到过的远端消息**仍用估算(可接受——它们不在视口内,只影响 maxScroll 总量估算,滚动条 thumb 长度有轻微误差,不影响正确性)。
- 每条消息只需测量一次(写入缓存后不再变),无持续性能开销。

#### 3c. 滚动条几何改用 `rowsOf`

`totalEstRows`、`thumbSize`、`thumbPos` 全部改用 `rowsOf` 累加。`scrollbarWidth=3`、`trackHeight = viewportHeight - 2` 保持(这是滚动条自身结构,与消息无关)。

#### 3d. 自动跟随逻辑保留

`useEffect`(line 513 附近)的「near bottom 就 pin 到底」逻辑保留,只是判断阈值改用真实 `viewportHeight`。

### 步骤 4:`chat-input.tsx` — 让 yoga 自然算高,移除对魔法常量的隐含依赖

ChatInput 当前根 Box 无 `flexShrink`/`height`,自然撑开——这其实**已经正确**。改动很小:
- 在根 Box 显式加 `flexShrink={0}`(防止 Body 收缩时压缩输入区)。
- 补全弹窗出现时,由于它在 `InputRegion`(`flexShrink={0}`)内,yoga 会自然把整个 InputRegion 撑高,**Body 的 MessageListRegion 自动收缩** → `measureElement` 重测 → 视口自适应。**这正是当前魔法常量无法做到的**。
- 无需改 ChatInput 内部任何行数计算。

---

### 步骤 5:列感知(column-aware)最小修正

利用 `useStdout()` 已可拿到的 `stdout.columns`(当前代码完全没用):
- `welcome.tsx` 的 55 列 ASCII logo:加 `if (columns < 60) 渲染精简版 else 完整版`,避免窄终端溢出。
- `messages.tsx`/`approval.tsx` 的字符截断(`slice(0, 80)`、`slice(0, 200)`):改用 `columns - margin` 动态截断。

(范围控制:这两处只做最小修正,不做全量 CJK 宽度库引入——那是后续阶段。)

## 验证方式

无测试 runner(AGENTS.md 明确)。用 `tsc --noEmit` 验证类型(在 `tui/` 目录)。运行时验证靠手动启动 TUI,重点测:
1. 调整终端窗口大小 → 消息区平滑重排,输入区始终钉底。
2. 输入 `/` 触发补全弹窗 → 消息区按弹窗高度自动收缩(当前会裁剪)。
3. 触发 HITL 审批 → ApprovalMenu 出现,消息区收缩而非被裁剪。
4. 长消息(含中文、长 URL)→ 滚动条 thumb 大小与真实可见比例一致(当前明显失真)。
5. PageUp/PageDown/滚轮 → 滚动位置准确。

## 风险与回退

- **measureElement 在流式输出期间频繁触发**:deps 已限定为离散信号(消息数、phase 等),而非每 token。流式刷新靠 `scrollTick` 和现有的 near-bottom pin 逻辑,不依赖重测。
- **首帧 height=0 闪烁**:用 fallback(`rows - 8`)兜底,测量到位后替换;`incrementalRendering` 已开,闪烁极小。
- **回退**:改动集中在 3 文件,git 可整体 revert `app.tsx`/`messages.tsx` 恢复魔法常量方案。`use-element-size.ts` 是纯新增,删除无副作用。
