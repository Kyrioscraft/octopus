# 接入 LangSmith 追踪模型 API 响应

## 背景与关键发现

1. **LangChain v1 已内置自动 tracing**:当 `@langchain/core` 的 callback manager 启动时,若检测到 `LANGSMITH_TRACING=true` + `LANGSMITH_API_KEY`,会自动构造 `LangChainTracer` 并挂载到所有 LLM/tool/子 agent 调用上。`langsmith@0.7.17` npm 包已作为 `@langchain/core` 的 peer dep 装好,**不需要新增依赖**。
2. **命名冲突陷阱**:现有 `LANGSMITH_API_KEY` / `LANGSMITH_PROJECT` 在 `core/src/settings.ts:129-131` 和 `model_config.ts:472-482` 中已被复用为 **LangSmith Sandbox**(deepagents 托管代码执行 VM)的凭证。直接设这两个变量会同时影响 sandbox 和 tracing —— 如果你不用 sandbox,问题不大;如果两者都用,需要小心。
3. **回调注入点**:`langgraphConfig` 是个 `Record<string, unknown>`,在 `server/src/routes/chat.ts:275-281`(/agent)和 `:367-370`(/resume)构造。LangGraph 的 `RunnableConfig` 原生支持 `callbacks` 字段,会沿 graph 传播到每个嵌套的模型/工具调用。

## 方案设计

采用**双层策略**,既支持零代码快速验证,又有明确开关和隔离避免冲突:

### 第一层:零代码自动 tracing(默认,无需改代码)
在 `server/.env` 中设置标准 LangChain 环境变量即可自动启用。这是最简单、最不易出错的路径,适合先用免费额度试一下。

### 第二层:代码增强(解决冲突 + 更好的可观测性)
- 新增独立的 `OCTOPUS_LANGSMITH_TRACING_*` 环境变量,与 sandbox 的 `LANGSMITH_*` 完全隔离。
- 显式构造 `LangChainTracer` 单例,通过 `langgraphConfig.callbacks` 注入到 graph 流中。
- 在服务启动时打印 tracing 状态日志,避免"我不知道有没有生效"的困惑。

### 2. 新文件 `packages/server/src/langsmith-tracing.ts` — tracer 单例工厂

```ts
import { Client } from "langsmith";
import { LangChainTracer } from "@langchain/core/tracers";
import type { BaseCallbackHandler } from "@langchain/core/callbacks/base";
import { getSettings, getLogger } from "@octopus/core";

let tracer: BaseCallbackHandler | null = null;
let initialized = false;

export function getLangSmithTracer(): BaseCallbackHandler | null {
  if (initialized) return tracer;
  initialized = true;

  const s = getSettings();
  const logger = getLogger("server.langsmith");

  if (!s.langsmithTracingEnabled) {
    logger.info("LangSmith tracing disabled (set OCTOPUS_LANGSMITH_TRACING=true to enable).");
    return null;
  }

  const apiKey = s.langsmithTracingApiKey;
  if (!apiKey) {
    logger.warn(
      "LangSmith tracing enabled but no API key found. " +
        "Set OCTOPUS_LANGSMITH_TRACING_API_KEY or LANGSMITH_API_KEY.",
    );
    return null;
  }

  try {
    const client = new Client({
      apiKey,
      apiUrl: s.langsmithTracingEndpoint,
    });
    tracer = new LangChainTracer({
      projectName: s.langsmithTracingProject,
      client,
    });
    logger.info(`LangSmith tracing enabled`, {
      project: s.langsmithTracingProject,
      endpoint: s.langsmithTracingEndpoint ?? "default",
    });
  } catch (err) {
    logger.exception("Failed to construct LangSmith tracer", err as Error);
  }

  return tracer;
}
```

> 用 lazy singleton 模式,避免在 import 阶段就读 settings。

### 3. `packages/server/src/services/chat.service.ts` — 注入 callbacks

在 `streamChat`(第 509 行)和 `streamResume`(第 669 行)两处调用 `input.agent.stream(...)` 时,把 tracer 注入到第二参数:

```ts
// streamChat (~509)
const tracer = getLangSmithTracer();
const eventStream = await input.agent.stream(
  { messages: [{ role: "user", content: input.userMessage }] },
  {
    ...input.langgraphConfig,
    streamMode: ["messages" as const],
    ...(tracer ? { callbacks: [tracer] } : {}),
  },
);
```

`streamResume` 同理改动。

> 为什么选这里:`langgraphConfig.callbacks` 会沿 LangGraph 的 run config 传播到每个嵌套的模型/工具/子 agent 调用,覆盖全图。比 wrap model 更稳(不受 `ConfigurableModelMiddleware` 运行时换 model 影响),也比 wrap middleware 更对(中间件协议没有 callbacks 通道)。

### 4. `packages/server/src/app.ts` 或 `main.ts` — 启动时初始化

在 server 启动序列中(推荐 `main.ts:27` `createApp()` 之前)调用一次 `getLangSmithTracer()`,让启动日志在服务监听前打印,方便确认配置生效。

当前仓库无 `.env.example`,新增一份示例文件,列出所有 tracing 相关变量及其含义,降低后续维护心智。

## 不在本次范围内的事项

- **不修改 deepagents SDK 调用**:`createDeepAgent({...})` 不接受 `callbacks` 字段(已确认 SDK 类型定义),但 `langgraphConfig.callbacks` 是 LangGraph 层注入,绕开 SDK 限制。
- **不增加新的持久化层**:trace 数据完全存在 LangSmith 云端,本地不落文件(你之前选了 LangSmith 方案,文件方案已弃用)。
- **不改动 sandbox 相关逻辑**:现有 `LANGSMITH_API_KEY` → sandbox 的路径保持原样,只是新增的 `OCTOPUS_LANGSMITH_TRACING_*` 优先级更高,不会污染 sandbox。

## 用户使用流程(实施完成后)

1. 注册 LangSmith 账号,拿一个 API key(免费 5K traces/月)。
2. 在 `server/.env` 中加:
   ```
   OCTOPUS_LANGSMITH_TRACING=true
   OCTOPUS_LANGSMITH_TRACING_API_KEY=lsv2_sk_xxx
   OCTOPUS_LANGSMITH_TRACING_PROJECT=octopus-dev
   ```
3. 重启 server,看启动日志确认 `LangSmith tracing enabled`。
4. 发起对话,在 https://smith.langchain.com 看 trace 树:每个模型调用的 prompt、response、tool_calls、reasoning、token 数、延迟都能看到。

## 验证方式

由于无 test runner,验证方式:
- `cd packages/core && npm run build` / `cd packages/server && npm run build` 确保 tsc 通过。
- 启动 server,确认日志显示 tracing 状态。
- 发一条测试消息,在 LangSmith UI 看 trace 是否出现。
- 关掉 `OCTOPUS_LANGSMITH_TRACING`,确认 fallback 行为(不注入 callbacks,启动日志显示 disabled)。
