## 目标

把 TUI 启动命令从 `pnpm start:tui` / `octopus` 简化为简短好记的 **`oc`**，同时保留向后兼容。

## 改动方案（三处）

### 1. `tui/package.json` —— 新增 `oc` bin 别名

在现有 `bin` 字段中加入 `"oc"`，保留原有 `octopus` / `octopus-tui` 以兼容旧用法：

```json
"bin": {
  "oc": "dist/cli.js",
  "octopus": "dist/cli.js",
  "octopus-tui": "dist/cli.js"
}
```

### 2. `tui/src/cli.ts` —— 调整 `program.name()` 与帮助文案

- 把 `program.name("octopus-tui")` 改为 `program.name("oc")`，使 `oc --help` 显示的命令名与实际一致。
- runInteractive 里 TTY 报错提示中的 `octopus-tui -n -p "..."` 示例改为 `oc -n -p "..."`。
- 其余逻辑（Commander 解析、子命令、ServerManager 自动起服务等）不变 —— bin 名只是入口别名，不影响 `program.name()` 之外的任何解析行为。

### 3. 根 `package.json` —— 新增 `pnpm oc` / `pnpm oc:dev` 短脚本

新增两个短脚本别名（保留现有 `start:tui` / `start:tui:dev`）：

```json
"oc": "pnpm build:tui && node tui/dist/cli.js",
"oc:dev": "pnpm build:libs && node --watch tui/dist/cli.js"
```

> 说明：`pnpm oc` 与原 `pnpm start:tui` 行为完全一致（先 build 再启动），只是名字更短。

## 使用方式（改动后）

**仓库内（日常开发，最常用）：**
```bash
pnpm oc          # 构建 + 启动 TUI（等价于原 pnpm start:tui）
pnpm oc:dev      # 构建依赖 + 自动重启模式
```

**全局安装（任意目录直接敲 `oc`）：**
```bash
# 一次性注册（在仓库根目录执行）
pnpm --filter @octopus/tui link --global

# 之后任意目录
oc                # 启动 TUI
oc -n -p "hi"     # 非交互
oc agents         # 子命令
oc --version
```

**向后兼容：** 原 `octopus` / `octopus-tui` bin 名、`pnpm start:tui` 脚本均保留，旧文档/脚本不受影响。

## 验证

1. `cd tui && npm run lint`（即 `tsc --noEmit`）确认 `cli.ts` 改动无类型错误。
2. `pnpm oc` 实际跑一次，确认 TUI 正常进入交互界面（ServerManager 自动起服务）。
3. `pnpm oc -n -p "ping"`（需 server 已起）确认非交互模式仍工作。
4. `pnpm oc agents` / `pnpm oc skills` 确认子命令不受影响。

## 不做的事

- 不删除 `octopus` / `octopus-tui` bin 名和 `start:tui` 脚本（向后兼容）。
- 不自动执行 `pnpm link --global`（这是用户一次性手动操作，且会影响全局环境，应在实施时征得同意后再跑）。
- 不改子命令名（`agents`/`skills`/`threads`/`mcp` 保持不变）。
