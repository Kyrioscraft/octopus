## 第 2 步:逻辑解耦(agent.ts 拆分的核心)

1. **graph-builder.ts** — 从 agent.ts 抽出图编译 + 签名缓存(`graphCache` Map、signature key 计算、缓存命中判断),暴露 `buildAndCacheGraph(config, agent)`。
2. **model.ts** — 抽出 `buildChatModel`(provider 解析 → ChatOpenAI/ChatAnthropic 分支)与 `generateTitle`,不再与图逻辑混在一起。
3. **wiring.ts** — 抽出中间件栈装配(13 个 middleware 的顺序化组装)与工具装配(builtin tools + MCP tools + HITL tools + 技能注入到 subagents)。
4. **打破 config⇄presets 循环** — `AccessMode`、`DESTRUCTIVE_TOOLS` 移入 `agent/access-mode.ts`;`config/` 不再 import 预设;`presets.ts` 单向依赖 access-mode + permission。
5. **subagents 收敛** — 内置子代理数据(EXPLORE/GENERAL_PURPOSE)与 FS 扫描 `listSubagents` 合并到 `agent/subagents.ts`,消除 4 处分散。
6. **model_config 解耦** — provider 注册/解析与 sandbox 凭据持久化拆成 providers/registry.ts 与 providers/sandbox.ts 两个模块。

## 第 3 步:API 兼容
- `index.ts` 重新导出的符号集合与现状**完全一致**(包括 createAgent 弃用别名)。
- `server` 包只通过 `@octopus/core` 包名导入,不需要改任何 import。
- 每步完成后运行 `cd packages/core && npx tsc --noEmit` 验证;最终跑 server 包 typecheck 确认无破坏。

## 不做的事
- 不改运行时行为、不改流式协议、不改权限语义。
- 不动 middleware/ 与 permission/ 内部(已是良好结构)。
- 不迁移 server 专属逻辑(ServerConfig 命名等)——避免波及 server 包。
