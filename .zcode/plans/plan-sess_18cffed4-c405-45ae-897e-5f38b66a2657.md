## 根因

`packages/core/src/skills.ts:137` 的 `_scanSkillsDir()` 内部使用了 `require("node:fs")`，但 core 是 ESM 包（`"type": "module"`），运行时 `require` 未定义，抛出 `ReferenceError` 被静默捕获 → 目录扫描恒为空 → `listSkills()` 发现不到任何文件 skill，包括两个内置 skill（`remember`、`skill-creator`）。

## 修复步骤

1. **`packages/core/src/skills.ts`**：删除 `_scanSkillsDir` 内的 `const { readdirSync } = require("node:fs")`，改为在文件顶部已有的 `import { existsSync, readFileSync, statSync } from "node:fs"` 中加入 `readdirSync`（与项目 `node:` 协议约定一致）。
2. **（防御性，可选）`packages/server/src/routes/config.ts`**：将 `GET /skills/builtin`（L161）与 `POST /skills/:name/install` 移到 `GET /skills/:name`（L99）之前，避免将来路由器实现变化导致遮蔽。Hono 当前静态路由优先，此步不改也不影响功能。
3. **构建验证**：`cd packages/core && npm run build`（重新编译并复制 built_in_skills 到 dist），再 `tsc --noEmit` 验证 core 与 server。
4. **运行时验证**：启动 server 后请求 `GET /api/config/skills`，确认返回的列表中包含 `remember` 与 `skill-creator`（origin 为 builtin），`GET /api/config/skills/builtin` 也能返回目录。
